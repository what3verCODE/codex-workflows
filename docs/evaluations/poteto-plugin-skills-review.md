This inventory is the pre-change evaluation of the 19-skill kit. The later user-selected changes are recorded in [the selection report](skill-kit-selection.md).

The [combined selection report](skill-kit-selection.md) applies the final priorities across all sources after your clarification about frontend, services, CLI tools and large projects with multiple agents.

Reviewed on 2026-09-12 at [74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12](https://github.com/poteto/plugins/tree/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12). This report covers all 35 SKILL.md files outside pstack. The companion [pstack report](poteto-pstack-skills-review.md) covers its 34 files. Together there are 69 files and 67 unique skill names. The two duplicate names are pr-review-canvas and thermo-nuclear-code-quality-review. The quality-review copies are identical; the canvas copies are different implementations.

Ranks below reflect marginal value for the existing 19-skill kit, across frontend, services, CLI tools and large projects with multiple agents. They are judgments from source inspection, not measured model performance. ADD means adopt a small maintained port after the changes below. OPTIONAL means add for a recurring need. BORROW means use selected instructions in an existing skill. SKIP means leave it outside this kit, not that its intended users should avoid it.

The actual skill bodies and relevant bundled assets, agent definitions, and runtime references were inspected. No external skill workflow was executed, and no skills were installed. This is a design and portability review, not a complete security audit of all bundled scripts.

A skill installation is not a full plugin installation. The repository keeps some required agents, hooks, and configuration beside its skill directories. Check those dependencies explicitly before adopting a wrapper. The [skills CLI documentation](https://github.com/vercel-labs/skills#install-a-skill) describes skill selection and direct skill paths; the [Poteto repository layout](https://github.com/poteto/plugins/tree/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12) shows the additional plugin components.

For the HTML PR canvas, the skill's own sample applies jq once per API page and redirects output to a file later read with json.loads. Multiple pages can therefore produce multiple top-level JSON values. Retrieve all pages into one validated object before assembly. Preserve a raw-diff view because the renderer deliberately filters import-only lines. These are reasons to port and test the artifact generator before relying on it for review.

For the three recommended additions, narrow triggers to the actual task, preserve project authorization rules, use the kit's file-based references, and keep supporting resources and licenses pinned. The PTY example illustrates a technique rather than a production harness. Reuse the runtime's PTY tools or a project harness where possible.
