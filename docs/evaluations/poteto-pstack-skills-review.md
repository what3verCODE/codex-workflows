# Pstack skills review

This inventory is the pre-change evaluation of the 19-skill kit. The later user-selected changes are recorded in [the selection report](skill-kit-selection.md).

The [combined selection report](skill-kit-selection.md) applies the final priorities across all sources after your clarification about frontend, services, CLI tools and large projects with multiple agents.

Reviewed 2026-09-12 against poteto/plugins commit `74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12`. Read all 34 skill entry points and selected supporting prompts, playbooks and the TSV helper. This is a source review, not a runtime benchmark. The ranking weighs marginal value for the existing kit in `manifest.json`, professional development use, operating cost and Codex portability. It does not claim measured quality gains.

My recommendation is to keep the local `unslop`, `tdd`, `code-review` and execution workflows. Within pstack, add a Codex adaptation of `how` first. Consider a smaller `why` next if historical design investigation is frequent. Borrow the audit format from `show-me-your-work` into the existing execution workflow. Do not add the full pstack bundle or its 20 principles as separate skills.

Ranks compare practical adoption priority. ADD means adapt before installation, KEEP means retain the existing local equivalent, BORROW means incorporate a bounded idea without adding another trigger, and SKIP means no current kit change. The principle rows use the exact source names so every entry is accounted for.

## Codex adoption constraints

Pstack orchestration refers to Cursor's `Task`, `generalPurpose`, `poteto-agent`, `run_in_background`, `readonly`, `AskQuestion`, workspace transcript layout and built-in `create-skill`, `babysit` and `/loop`. Poteto-mode also expects `cursor-team-kit` skills. Copying Markdown does not supply these capabilities. Model defaults are configurable, but the defaults contain `composer-2.5-fast`, `claude-opus-4-8-thinking-xhigh` and `gpt-5.5-high-fast`. None is an available model slug in this session. The available Codex agents also cannot satisfy a requirement for another provider's model family simply by selecting a different OpenAI model. See [mode](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/poteto-mode/SKILL.md) and [model setup](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/setup-pstack/SKILL.md).

The autonomy rules need selective adaptation. The user's preference supports progress on authorized reversible work. Poteto-mode goes further by allowing team chat and tracker actions without asking. Its opening-PR playbook also proposes destructive worktree recovery commands. Those instructions do not create authorization and conflict with this session's messaging restrictions. Retain the kit's current authority boundaries. See [autonomy](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/poteto-mode/SKILL.md#autonomy) and [opening a PR](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/poteto-mode/playbooks/opening-a-pr.md).

The review method has useful evidence checks but also tension. Its lead guidance rejects speculative style findings, while its code-quality reference treats structural preferences and crossing 1,000 lines as presumptive blockers. Preserve concrete execution-path evidence in the existing code-review rather than copying those thresholds. See [lead judgment](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/interrogate/references/lead-judgment.md) and [code-quality reference](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/interrogate/references/code-quality-review.md).

For a first addition, adapt `how` to the current explorer/scout roles, answer small questions locally, and make critique opt-in. For `why`, retain confidence tiers and source coverage but search proportionately to the question. For long jobs, reuse the [TSV helper](https://github.com/poteto/plugins/blob/74dd2291e8e37b12fd6dc49b2acbd655c6bdaf12/pstack/skills/show-me-your-work/scripts/log.sh) with one log owner and evidence links. This adds useful behavior while leaving one implementation and review system in charge.

No pstack-derived skill currently in the manifest warrants removal on this evidence. Its only existing pstack entry is the locally scoped `unslop`; keep it. The remaining recommendations are additions to consider or ideas to incorporate, not installed changes.
